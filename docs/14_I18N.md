# 14 — i18n

Same scheme as FrameLedger/CommandForge: `.resx`, `en` is the source of truth, `vi` and `ja` are satellites.

## Files

- `src/AppLedger.App/Resources/Strings.resx` (en), `Strings.vi.resx`, `Strings.ja.resx` — all UI strings.
- `src/AppLedger.Agent/Resources/Strings.resx` (+vi/ja) — the handful of strings the Agent emits (task description,
  event summaries rendered by the UI come from the UI resx, not the Agent).
- `SatelliteResourceLanguages=en;vi;ja` in `Directory.Build.props` so only those satellites are built/packaged.
- **Public** `Strings` class; XAML uses `{x:Static res:Strings.Key}`. The visibility is not a style choice:
  `{x:Static}` resolves through *public* reflection, so an internal class compiles cleanly and then throws when
  the window is constructed — "StaticExtension value cannot be resolved to an enumeration, static field, or static
  property". Nothing but running the app finds that (`24_ADR.md` §Findings, 2026-08-28).
- The resx files **and** the `Strings` class are generated together by `tools/gen-strings.py` and committed, rather
  than by `PublicResXFileCodeGenerator` as this document first said. That generator is a Visual Studio design-time
  step, so `dotnet build` on a machine without VS produces no class at all; the SDK's `StronglyTypedFileName`
  alternative writes into `obj` *after* the `Compile` items were evaluated, so a clean build generates the file and
  never compiles it while a second build succeeds — green locally, red on CI, which always builds clean. One script
  writing all four files has no build ordering in it, and the parity test in `AppLedger.App.Tests` is what keeps it
  honest if somebody edits a resx by hand.

## Key naming

`<Area>_<Element>_<Purpose>`: `Nav_Home`, `Page_App_Tab_Network`, `Metric_WsPrivate_Tooltip`, `Privacy_Gate_What_Body`,
`Event_NewHost_Summary`, `Error_PolicyDenied_Body`, `Unit_Bytes_MB`. Plurals: `_One`/`_Other` pairs chosen in code
(`Plural.Pick(count, Strings.X_One, Strings.X_Other)`). Placeholders: `{0}`-style with a comment in the resx `comment`
column describing every argument (`{0} = app name, {1} = byte count formatted`).

## Rules

- No string concatenation of fragments; full sentences per key. No text in code except log messages and exception messages.
- Formatting through `Formatters`: bytes (`B/KB/MB/GB/TB`, binary vs decimal per setting, default binary like Explorer),
  percentages (one decimal), durations (`1h 23m`), relative times ("4 min ago"), dates (`CultureInfo.CurrentCulture`).
- Culture: `settings.language` (`en`/`vi`/`ja`/`system`) → `CultureInfo.CurrentUICulture` set before the Host builds;
  changing it requires restart of the UI (documented in the setting row).
- `ja` may be machine-drafted; mark each such key with `<comment>review</comment>` and list them in the PR.
- Never localize: app ids, `app.display_name` from PE/catalog (shown as-is), file paths, hostnames, SQL, log event names.
- Fonts: WPF-UI's default Segoe UI Variable handles `vi`; for `ja` rely on font fallback (Yu Gothic UI); test both
  themes with `ja` for clipping in cards and chips.

## Event and alert text

Events store a `kind` + JSON payload; the UI renders localized summaries (`Event_<Kind>_Summary` with payload fields),
so history stays language-neutral and switching language re-renders old events correctly.
